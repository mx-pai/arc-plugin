# Arc Plugin 设计与实现 Plan

状态：v0.1.0 已实现并完成隔离环境验证，桌面原生按键与分屏保留手动验收项

## 产品约定

增强 Chrome 当前原生竖向标签栏，恢复 Arc 的空间、固定入口、统一搜索、关闭与恢复习惯，用户未来可以自行增加能力

入口为工具栏弹窗、⌘T 新标签页、⌘⇧K 居中命令面板、`arc` 地址栏关键字和设置页，Chrome 原生侧栏与标签外观由浏览器继续呈现

最高优先级验收是键盘调用后可以输入、选择结果、切换页面和取消，Cmd+T 的地址栏焦点与保留快捷键限制单独记录，通过 API 验证与原生键盘验证区分完成度

## 界面与交互设计

搜索面板使用系统字体、13–14px 正文、约 40px 的结果行，浅雾紫底色 #ECE8F4、正文 #302C38、浮层 #F8F7FA、选中 #DCD4EC、细线 #D7D0E0，左右对齐围绕标题、网址与动作提示，图标以字母缩略标识和简单线性符号呈现

顶部为搜索输入，下面为工作、OKR、个人空间切换，结果包含已打开页面、固定入口、空间与命令，底部展示快捷键提示和设置入口，页面入口按用途使用相同搜索组件

```text
工具栏弹窗 / 新标签页 / 网页命令面板
  搜索网址、标签、收藏或命令
  [工作] [OKR] [个人]
  已打开页面 / 固定入口 / 空间 / 命令
  ↑↓ 选择   Enter 打开   Esc 关闭

设置页
  空间与固定入口
  Arc 导入预览 / 备份 / 恢复
  快捷键 / 已支持能力 / 待验证边界
```

新标签页保留 Chrome 默认地址栏输入优先级，网页命令面板在快捷键用户操作后主动聚焦自身输入，Esc 关闭后恢复原页面焦点，受限页面使用工具栏弹窗

设计复核：主交互围绕搜索与切空间，界面不增加常驻第二侧栏，迁移设置页集中呈现数量、层级与异常，操作名称与实际数据变化一一对应

## 数据模型

Space：稳定 ID、名称、颜色、顺序、书签目录 ID，可关联一个或多个窗口的原生分组

Item：稳定 ID、Arc 原始 ID、所属空间、父节点、子节点顺序、类型、名称、原始网址、固定状态和可选书签 ID，类型包括 folder、link、split

Archive：ID、空间、标题、网址、归档时间和可选最近会话 ID，恢复成功后移出归档，固定入口继续保留

Runtime：当前窗口空间、原生分组绑定、固定入口与打开页面的绑定、各空间最后激活页面，保存于 storage.session

PersistentState：schemaVersion、revision、spaces、items、archives、导入记录、上次恢复快照、原生分组恢复线索，保存于 storage.local

收藏条目的身份由独立 ID 决定，同网址的两条收藏可以位于不同空间，原始网址和正在浏览的网址分别处理

## 状态与浏览器规则

切空间时激活目标空间上次有效页面，展开对应原生分组，收起同窗口其他托管分组，空空间按需打开新标签页，已有非托管分组通过“接入当前分组”显式关联

新页面优先继承 opener 的空间，普通新标签继承当前窗口空间，跨窗口移动时以目标托管分组的空间为准，移出托管分组后解除该页面的运行绑定

原生分组重命名同步更新所属空间名称，原生分组关闭保留空间数据，用户已有的其他分组保留自身状态

点击固定入口优先复用当前窗口明确关联的页面，否则按保存网址打开，关闭页面解除运行关联，用户移除收藏时才更新目录，原生书签修改在刷新时同步，外部删除采用有提示的失联状态处理

首版已完成原生书签创建、导入、更新补偿和移除，原生书签界面的完整双向编辑同步安排在后续版本，Chrome 设置页和新标签页保留上一个真实网页的操作上下文

浏览器重启后通过组名与保存的 URL 顺序寻找唯一候选，存在歧义时等待显式接入，同一后台的写入通过串行队列协调，页面事件重新查询浏览器状态

## Arc 迁移契约

输入接受 StorableSidebar JSON 和本项目的 JSON 备份，大小限制、schema 检查与数量上限在解析前执行

交错字典数组转换为 Map，分别收集命名 Space、窗口本地容器和 itemContainer 根节点，通过 parent/children 与根可达关系构造树，忽略 sidebarSyncState 和 firebaseSyncState 缓存

窗口临时页单独形成可见的导入空间，避免与命名空间推测合并，pinned/unpinned 根保留语义，topApps 作为跨空间收藏，空目录保留，重复网址保留，循环和缺失引用形成诊断

http/https 网址可打开，脚本、data、扩展私有页面等输入列入跳过报告，分屏保留子项、方向与比例，双页可调用 Chrome 原生分屏，三页和四页组合提供逐项打开入口

预览 → 校验 → 保存恢复快照 → 创建本次专属书签目录 → 提交扩展状态，写入失败清理本次创建的目录，撤销导入恢复快照与本次书签创建清单，重复导入按 Arc 原始 ID 更新

导入时复用同名且尚无保存内容或分组记录的初始空间，已有实际内容的空间保持独立，重复导入相同内容采用无写入返回并保留原撤销快照

每次书签创建前保存父目录、名称、网址和原有子节点 ID，创建成功后记录新 ID，中断恢复时查找唯一新节点并补偿，多候选时提示人工核对，独立编辑 Chrome 书签导致的歧义会保守保留数据

导出包含版本、空间、目录、固定入口和归档，书签与标签等运行 ID 在恢复时重新生成

## 权限与模块边界

| 模块      | 来源                          | 写入目标             | 用户操作     |
| --------- | ----------------------------- | -------------------- | ------------ |
| search    | tabs、items、spaces、commands | 搜索结果             | 输入与选择   |
| workspace | Space、tabGroups              | 托管分组、Runtime    | 切换或接入   |
| pin       | 当前页面、Item                | 专属书签、items      | 保存固定入口 |
| archive   | 当前页面、Space               | archives、tabs       | 归档与恢复   |
| import    | 用户选择的本地文件            | 预览、快照、专属目录 | 确认导入     |
| spotlight | 用户触发的 activeTab          | 隔离样式的临时界面   | 快捷键       |

实现从纯函数模型、解析与搜索开始，再接浏览器适配和 React 入口，新增能力添加明确命令处理分支，继续使用现有模型与保存路径
